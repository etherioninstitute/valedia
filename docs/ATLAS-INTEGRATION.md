# ATLAS research integration

ATLAS commit cf4349f15c9d68a67042f792973372f2e0231088 contributes the Janus idea of weighting research cohorts by measured outcomes and exposing disagreement. This implementation is standard-library-only and import-pure. It does not import upstream modules, use their placeholder reward scoring, recreate absent proprietary prompts or implement the documented but missing 25-agent runtime. See ATLAS-LICENSE.txt for the complete MIT notice and repository framework-scope note.

All features default disabled. Trusted local code explicitly constructs ResearchConfig(enable_cohorts=True) and optionally enable_scenarios=True. Model JSON must never choose this config. Typed recommendation evidence has source identity, SHA-256 and UTC observation time. Every cohort needs matured development-only outcomes with prediction before maturity before the decision cutoff. Caller must verify receipts and split assignment against its trusted data registry; a self-reported development label is no proof of provenance. Test/holdout observations must never enter this adapter or any feedback loop. Research signals are conviction-weighted opinions, not estimated returns or calibrated probabilities. Scenarios have separate hypothetical labels and assumptions; they are never measured outcomes.

Offline JSON intake: python -B src/atlas_research_cli.py --input research.json --enable-cohorts [--enable-scenarios]. Maximum input one MiB, 100 records per kind, 32 evidence records per item. Output goes to stdout. It cannot submit, approve or schedule anything. Without explicit feature flags, nonempty inputs are refused. Empty research produces no eligible proposal.

prepare_brain_leg accepts a validated ResearchArtifact and ReviewedBrainInputs supplied separately by trusted code after policy review. It prepares a buy leg only when an enabled cohort signal is positive. It never infers fused_score, expected_return_pct, track_record_mult, risk_factor, max_pct, pos_multiplier or concurrent_bets. A positive research signal or an LLM boolean is not execution approval. Review inputs must come from policy-controlled code, never deserialized model output. Leg identity hashes the complete research artifact and reviewed inputs. Caller binds that leg to a stable decision identity and an independently constructed recovery context. Changes require a new deliberate decision; replay with changed data under an old decision is refused by Journal.

Actual prepared entrypoints remain unified_brain.run_brain(recovery=...) and master_allocator.execute_allocations(..., recovery=...). Recovery context owns Journal, account, UTC day, decision identity and injected transport. The adapter cannot choose these, change caps/state/halts, approve live mode or bypass existing sizing/fee/intent guards. run_brain retains stage_kelly and the recovery daily-notional bound. This slice has no actual broker transport or automatic execution API. The verification harness uses a fake callable under an OS network denial.

The three default paths for Journal, halt and ping now derive from trusted module location: application-root/state. They cannot be selected per order. An isolated candidate naturally uses its own state; after reviewed source promotion defaults naturally map to the existing accepted state. No candidate databases or halt files belong in promotion.

Bounded-simplex weighting uses softmax of mean matured signed development returns followed by Euclidean projection onto sum-one lower/upper bounds; infeasible cohort counts and bounds are refused. These outcomes are externally measured inputs, not copied upstream performance claims. Neither framework promises profitable trading. Autonomous prompt/source/model changes, model/provider access, research memory, generated-data scoring and scheduled loops remain unsupported.
